# Security review, 2026-11

A read-through of the server, engine, adapters, runner and apps (web and phone) at `bdad799fd2` (main), plus two
`bun -e` measurements for the complexity cases. Each finding names the file and line where it was, the way it fails,
and what changed. Fixed findings have a regression test; what stays open is listed as open.

Areas covered: the HTTP and auth surface, tenant isolation, secrets and cryptography, SSRF/uploads/parsing, the Tool
Gateway and connected computers.

## Fixed

### 1. `outboundFetch` without a guard on a default self-host (high)

`packages/engine/src/net-guard.ts:517` returned the runtime `fetch` whenever the private-network switch was on and no
allow-list was set — which is the default of a self-hosted server closed to sign-up (`ALLOW_SIGNUP` false). That branch
had no https-only check, no check of the resolved addresses, no pinned socket and no `redirect: "manual"`. The MCP
transport (`connectors/mcp.ts:186`) sets no `redirect`, so a `307` from a public MCP server was followed to
`http://169.254.169.254/…` or `http://10.x/…` carrying the connector's secret headers.

The unpinned branch stays, because a LAN or tailnet address is the switch's point, but every hop now goes through a
check (the addresses no setting lets through: loopback, link-local and the metadata addresses) and redirects are
followed by us with `fetch`'s semantics (307 and 308 send the request again; 301, 302 and 303 ask for a GET). With an
allow-list, the request stays pinned as before. ADR 0210 §7.

Tests: `packages/engine/test/net-guard.test.ts` (a refused hop, and redirects followed with each hop checked) and
`connector-headers.test.ts` (a same-origin 307 keeps method and headers; a 302 becomes a GET).

### 2. Root writing through a symlink in a lent account folder (high, system mode)

`apps/server/runner/json-file.ts` wrote its temporary with `writeFileSync(tmp)` and `renameSync`, following a link.
The sequence: the owner signs in again to an account (`again` writes no `.signing-in`, `accounts.ts:1849`), `lendTo`
refuses only by `.signing-in` (`:2932`), and the agent borrowing the account plants `provider.json.<pid>.0.tmp` as a
link to a file it owns; when the owner submits the code, `keepKey` (`:2190`) writes the new key through the link, and
`provider.json` becomes a link.

The temporary is now created with `O_EXCL|O_NOFOLLOW` and written through its own descriptor, with a fresh name when
the previous one exists; the key always lands in a file this call created, and the `rename` puts it in place.

Test: `apps/server/test/runner/accounts.test.ts` ("a link an agent's user leaves where a re-sign-in writes never takes
root's key").

### 3. Quadratic regexes on the event loop (medium-high)

- `packages/adapters/src/outbound-url.ts:38`: `/\/+$/` over `URL.toString()`. Measured: 40,000 slashes and a character =
  **1,219 ms**; 20,000 = 321 ms. Reachable from any page an agent reads (`outbound.ts:72-111`, `urlsIn`).
- `packages/adapters/src/error-scrub.ts:4` (`EMAIL`, `JWT`) ran over runner log lines with no per-line cap
  (`problem-report.ts:348` cuts nothing). Measured: 40,000 repetitions of `a.` = 823 ms; 80,000 = 2,307 ms.

Fix: `normalizeUrl` trims by index; `scrubLogLine` cuts the line at `LOG_LINE_MAX` before any regex (the rest was
never shown anyway).

Tests: `packages/adapters/test/outbound-url.test.ts`, `error-scrub.test.ts`.

### 4. A viewer widening a restricted file through an agent (medium)

`moveToSharedDrive` (`packages/engine/src/artifacts.ts:1816`) required only the agent's `writable` plus
`addsToDrive` of the person behind the run (`upload_files`, which everyone holds by default). For a file with limited
editors, someone who only views it could mention the agent in the file's conversation and ask for the move: the agent
reaches the conversation (`agentReaches`), edits (`agentBase` null ⇒ `edit`) and moves it, so the file becomes the
workspace's — something the person path (`setFileSharing`, which requires `readsItThere && personEdits`) did not
allow.

`sharedDriveRefusal` now applies `readsItThere(asker)` and `personEdits(asker)` too: an agent widens no further than
the person would. ADR 0157, amendment of 2026-11-22.

Test: `packages/engine/test/drive-saves.test.ts` ("a member who only views it can't widen it through an agent").

### 5. Incomplete credential redaction (medium)

`redactCommon` (`packages/adapters/src/redact.ts`) covered few shapes: Stripe (`sk_live_`/`rk_`/`whsec_`), Google
(`AIza`), GitLab (`glpat-`), npm (`npm_`), Hugging Face (`hf_`), JWTs (`eyJ…`) and PEM blocks were missing; `auditInput`
(`packages/engine/src/agent-audit.ts:27`) masked by name and did not cover `key`, `auth`, `dsn`, `session`,
`signing_key`. What slipped through reached `audit_log`, the operator API's review block and the runner's activity log.

Tests: `packages/adapters/test/redact.test.ts` (one assertion per shape, and PEM as one value) and
`packages/engine/test/agent-audit.test.ts` (`key`/`auth`/`dsn`/`signing_key`/`session`).

### 6. Machine socket: a large frame before the token; a non-constant compare (low)

A socket on `/api/machines/connect` authenticates after the upgrade; `machine-hub.ts:1577` called `parseRunnerFrame`
before any check, and `MAX_FRAME_BYTES` is 8 MiB. Many sockets without `Origin`, each with one large frame, cost a
buffer and a synchronous `JSON.parse`. Before the hello, the frame is now read up to 64 KiB (a hello is a few hundred
bytes). `b.token === frame.token` became `safeEqual` in `mcp.call`/`mcp.list` (`machine-hub.ts:1611,1614`).

Tests: `packages/engine/test/machines.test.ts`, `machine-reconnect.test.ts` and `machine-accounts.test.ts` keep
passing (63 + 75 + 45 cases).

### 7. NAT64 and 6to4 not classified (low)

`isBlockedAddress` handled mapped/compatible, fc00/fe80/ff00, but an AAAA `64:ff9b::a9fe:a9fe` (NAT64 to
169.254.169.254) or `2002:a9fe:a9fe::` (6to4) passed as public. Both prefixes are now unwrapped and judged by the
embedded IPv4, in `isBlockedAddress` and in `plainAddress` (used by `alwaysBlocked`).

Test: `packages/engine/test/net-guard.test.ts`.

### 8. The in-memory rate limiter grew without a cap (low)

`packages/adapters/src/rate-limiter.ts` swept the map only above 50,000 keys, and only expired windows; with forged
keys (an `X-Forwarded-For` with no trusted proxy) every call became a sweep. There is now a hard cap
(`MEMORY_LIMIT_KEYS`, 100,000): expired windows go first, then the oldest. Test in
`packages/adapters/test/adapters.test.ts`.

### 9. `ac-slider` without escaping its numbers (low)

`packages/client/src/lib/block-kit.ts:184` interpolated `min`/`max`/`step` into `innerHTML` without `esc()`. The values
come from the spec (numbers), but a value with a quote would close the attribute. Test in
`packages/client/test/blocks-lib.test.ts`.

## Changed in comments and ADRs only

- ADR 0210: §7 (redirects followed by us, hop by hop) and a consequence on NAT64/6to4; the "plain `fetch`"
  consequence now says the runtime no longer follows the redirect itself.
- ADR 0157: amendment of 2026-11-22 (the asker rule for `shared_drive`).

## Verified good (sample)

CSRF/origin on `/api/app` (`routes/app/context.ts:139-153`; `x-agentes-client` cannot be forged cross-site without a
preflight); cookies `httpOnly`/`lax`/`secure` from `PUBLIC_URL` (Better Auth 1.7.10); the WebSocket re-reads the session
from the database and checks membership; frame tickets are single-use; uploads and downloads (`attachment` + `nosniff`
+ `sandbox`), `<svg>` rebuilt from an allow-list; connection codes (8 chars, single-use, 10 min, hashed at rest) and
pairing (31^6, budget per user and IP); email codes and the owner claim (constant-time compares); OAuth with PKCE
S256, single-use decisions and an exchange bound to `client_id`/`redirect_uri`; constant-time signature checks
(routine hooks, webhooks, Telegram, git, GitHub App, human-pass); the git proxy (claims + revocation generation + repo
allow-list); static serving without traversal; CIMD https-only, pinned, no redirect, size and time capped.
